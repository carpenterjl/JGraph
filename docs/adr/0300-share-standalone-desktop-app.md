# ADR 0300 — Share > Standalone Desktop App: the share window and the script it runs

## Status

Accepted, 2026-11-03. Stage W12 of the App Designer window plan (decision WD3): the SHARE drop-down's Standalone Desktop App, the "Configure Standalone App for Sharing" window and Package. Share > MATLAB App waits for W13; Share > Web App stays disabled (web apps are out of JGraph's scope, compiler plan KD2, stage X2).

## Context

The DESIGNER tab's SHARE drop-down was disabled: `compiler.build.standaloneWindowsApplication` and the Standalone Application Compiler (K19) take an `.mlapp` (ADR 0278), but nothing in the designer reached them. R2025b's road, read in place: App Designer's `shareApp` hands the app to `AppSharingStrategyFactory`, whose `DesktopAppSharingStrategy.showProjectWebUI` opens `compiler.internal.ui.StandalonePreviewWindow`, a web window titled "Configure Standalone App for Sharing" (675 by 880, at most 80% of the screen, at least 500 by 280) over `toolbox/compiler/ui/share_window`'s page with `compiler_ui_common`'s words. The page holds App Appearance (the app's name and version from `getAppDetails`, "Images to be included in the app" with a splash screen and an icon selector, each Browse or Remove), "Files required for the app to run" (`runFileAnalysisWithProgressDialog` over the dependency graph, Add File and Add Folder, "No custom files currently added"), "Manage App Sharing with a MATLAB Project", and Package. Package calls `deployAppDesignerProject(app, 'standalone', files, images)`, which keeps no project: `StandaloneAppDesignerScriptBuilder` writes a build script and an installer script over `compiler.build` and `compiler.package`, and `StandalonePackageWindow` ("Standalone App Packaging Progress") runs them. The W0 probe `w0_share` recorded every variant of the scripts and two R2025b bugs: App Details' text is pasted into double-quoted strings as it is, so a description with a line break fails with `MATLAB:m_unterminated_string_literal` and one with a double quote with `MATLAB:m_missing_operator` (and `deployAppDesignerProject`'s catch block ends in a stray `ends`). Without a Compiler licence, `FeatureStatusStateProvider` leaves Share > Web App and Share > Desktop App disabled. The docs describe R2026b's share dialog; R2025b's page is what is built here.

## Decision

- **The scripts** (`JGraph.Deploy/AppShareScript`): the standalone build script (the options over the app, `AdditionalFiles` for the files listed, `OutputDir` `<app folder>\release\build`, `Verbose`, the splash screen and icon when chosen, `ExecutableVersion` from App Details, `compiler.build.standaloneWindowsApplication`), the installer script (`compiler.package.InstallerOptions(buildResult)`, `OutputDir` `release\package`, `Verbose`, the name, version, author, summary and description, `compiler.package.installer`) and the web app's, to R2025b's character, the W0 recording being the oracle. One correction: `Quoted` doubles a quote and joins a text's lines with `newline`, so what App Details holds reaches the options. JGraph's runtime delivery adds `packageOpts.RuntimeDelivery` only off R2025b's default (the runtime fetched while installing).
- **The analysis door** (`IScriptDependencyAnalysis`): the MATLAB session runs `requiredFilesAndProducts`' analysis over files on its script thread, from its current folder, path and built-ins; the shell hands the designer that door and its compiler-script runner (K19's, with the console's lines kept for the dialog's log).
- **The window** (`AppShareWindow`, "Configure Standalone App for Sharing"): App Appearance with the app's name and version from App Details and the two image selectors (the default pictures from `toolbox\compiler\packagingResources`, Browse, Remove, an image of another type refused in the selector's words); the files required (the analysis's files beside the app, Add File, Add Folder and Remove for the user's own, the placeholder when none); JGraph's Package Type (K18's three runtime deliveries in the compiler apps' words); Show Code over the whole script; Package. Package rests the button, opens the packaging dialog (`CompilerPackagingDialog` now takes a title, a name, a version and its steps) with "Building Standalone App" and "Creating Installer", runs the build script and then the installer script in the MATLAB session, each its own run so that each step reports on its own, and ends with "Process completed successfully" or "An error occurred while deploying", Show Log, and Open Output Folder on `release`.
- **The designer**: `AD_SHARE_ALL_OPTIONS` and `AD_SHARE_DESKTOP` are live; the drop-down is enabled with an app open and rests while the app's code runs. Share saves the app first as Run does (`SaveBeforeRun`: Save As for an app with no file, else the Code View's text taken and the file written when changed); one share window per app, brought up again when open; the window closes with the designer, as R2025b's does. An app whose App Details holds no name is packaged under its file's name. Web App stays disabled, as R2025b's is without a compiler.

## Consequences

- `JGraph.Deploy/AppShareScript.cs` (with `AppShareDetails`), `JGraph.Scripting/IScriptRepl.cs` (`IScriptDependencyAnalysis`, answered by `JgsReplSession`), `JGraph.Application/Scripting/AppShareWindow.cs`, `AppDesignerWindow.Share.cs` (the command, the runner and analyser doors), the toolstrip's `CommandFor` row and the drop-down's enabling, `CompilerPackagingDialog`'s general constructor, the shell's wiring in `ScriptWorkspaceWindow.Documents.cs`; `DesignActions`' live set.
- `run-w2designer.ps1` now expects the SHARE drop-down enabled with an app open.

## Measured

- **Tests**: `AppShareScriptTests` (6) hold the W0 recording's texts for the standalone script without and with files and images, the web app's, the runtime line, `Quoted` over a line break, a quote and an apostrophe, and the output folders; `AppDesignerToolstripTests`' rows for the two live ids. 89 pass in the share script, toolstrip and compiler apps suites.
- **The window check** (`run-w12designer.ps1`, JGraph.Application in Release over `w4/W4App.m`): all 42 checks pass - the SHARE drop-down enabled and opened, Web App shown and disabled, MATLAB App shown, Standalone Desktop App invoked; the window's name and version from App Details, the analysis ending with no file beyond the app and the placeholder shown, the default images, Show Code with the options over the app and the two output folders, no runtime line at the default and one after "Do not include MATLAB Runtime" is chosen; Package with the dialog's name, its two steps and "Process completed successfully", the program at `release\build\W4App.exe` and the installer at `release\package\MyAppInstaller.exe`, Open Output Folder enabled, Package enabled again; and the built program started under the staged JGraph Runtime 0.2.3 with `JGRAPH_RUNTIME_ROOT`, its window "MATLAB App" up, pictured, closed through `WindowPattern`, exit code 0. I looked at the pictures of the share window, the dialog and the running program.
- **A deployed app that takes input arguments**: the check first packaged `w8/W8bApp.mlapp`, whose startup takes an argument; the built program refused to start it with an error dialog and a beep ("Not enough input arguments. Error in => W8bApp.mlapp at line 13"), which is what a program whose main wants arguments does when started with none. The check packages the W4 app instead.
- **Older checks on this source**: `run-w8bdesigner.ps1` (Run's save, now `SaveBeforeRun`), `run-k19window.ps1`'s standalone run (the packaging dialog's constructor) and `run-w2designer.ps1` (the drop-down's state) - see the commit.

## Not measured

- **R2025b's own window** was not seen on screen; the page was read from its bundle and the W0 recording.
- **The system dialogs** - Add File, Add Folder, Browse - are not driven; `AddCustom` and the image choice are covered by the script tests' arguments, not in a window.
- **The installer** written by the check (runtime delivery None) was not run; the default delivery, which wants the runtime's MSI (`installer/JGraph.Runtime.Installer/bin/Release`), was not exercised in the check.
- **A plain-text app with required files** was not shared; the analysis's list was seen empty only.

## Divergences

- **No "Manage App Sharing with a MATLAB Project" pane**: R2025b offers adding the app to a packaging task in a new or an existing project; JGraph's projects and compiler tasks (K20, K21) are reached from the shell's Deploy menu and `compilerTaskManager`.
- **Package Type is on the page**: R2025b's page has no runtime choice (its script takes the installer options' default); JGraph shows K18's three deliveries so that a machine without the runtime's MSI can still package.
- **Show Code is on the page**: R2025b's page shows no script.
- **App Details' text is escaped** (a line break, a double quote) where R2025b's script fails.
- **An empty App Details name becomes the file's name** for the installer's `ApplicationName`; R2025b writes an empty one (its options would refuse it).
- **The files required are the session's analysis** (`requiredFilesAndProducts` from the session's folder and path), not R2025b's project-creation dependency graph with derived extensions filtered out; a folder added is passed as it is.
- **Package runs the build and the installer as two runs** of one script shown whole; Package is enabled again after a run, where R2025b's button rests until the window is reopened.
- **The look is JGraph's** (WPF expanders and buttons), not the web page's title panes and image boxes.
