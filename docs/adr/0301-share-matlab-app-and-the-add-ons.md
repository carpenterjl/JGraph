# ADR 0301 — Share > MATLAB App, the add-on packages and the Apps gallery

## Status

Accepted, 2026-11-03. Stage W13 of the App Designer window plan (decisions WD4 and WO4): Share > MATLAB App writing the toolbox file R2025b writes, the `matlab.addons.toolbox`, `matlab.apputil` and `matlab.addons` functions over JGraph's own add-ons folder, and the shell's Apps menu as the gallery.

## Context

Share > MATLAB App was disabled, and JGraph had no `.mltbx` or `.mlappinstall` support. W0 had measured that R2025b's App Designer writes `release\<app>.mltbx` through `matlab.addons.toolbox.packageToolbox` (no `.mlappinstall`, no log), that `matlab.apputil.create` is on its way out, and that the package is signed with MathWorks' key. The probes of this stage (`ui-probes/w13`) measured the rest: `MatlabAppDesignerScriptBuilder`'s script over five extra files of different kinds and every part R2025b writes - `[Content_Types].xml`'s defaults per extension (`m` and `txt` text, `mat` workspace data, `mlapp`, `png`), the manifest, the configuration's path entries ("" and "/sub"), `DesktopToolset.xml`'s `tool` with the app's uuid, label, callback, summary, description and generic icons - and a package made by hand through `ToolboxOptions` with an image and releases (the `primaryScreenShot.png` part with its two relationships, no configuration part without paths, the relationship ids sequential); the legacy `.mlappinstall` built with `appcreate.internal.buildapp` and read by `mlappinfo` (`metadata/appProperties.xml` with the entry point, name, version, GUID, author, products and app entries); what R2025b lays out when it installs each (`MATLAB Add-Ons\Toolboxes\<Name>` with the files and `resources\addons_core.xml`, `matlab_path_entries.xml`, `mltbx_app_gallery_registration.xml` and `screenshot.png`, the folders put on the path; `MATLAB Add-Ons\Apps\<dir>` with the app, a wrapper class, `addons_core.xml`, the icons, `matlab_compatibility.xml` and `mlappinstall_app_gallery_registration.xml` whose callback is `matlab.apputil.run('<id>')`; `getInstalledAppInfo`'s id `<dir>APP`, 'updated' on a second install; a toolbox's app is not among `getInstalledAppInfo`'s); `ToolboxOptions`' display, defaults and forty refusals; and the texts of the three APIs' refusals. R2025b's sources were read in place (`ToolboxOptions.m`, `packageFromOptions.m`, `PackageCommand.m`, `MlappUtils.m`, `toolboxVersion.m`, the `matlab.apputil` and `appinstall` files with the wrapper template, the `matlab.addons` files); `installToolbox`, `installedToolboxes` and `uninstallToolbox` are P-coded, so their documentation and the probes stand for them. The share page is the bundle's MATLAB app preview widget: the words that the app is packaged as a toolbox, the app card, the files required, the project pane and Package; the package window is "MATLAB App Packaging Progress" with the step "Packaging MATLAB App".

## Decision

- **The packages** (`JGraph.Deploy/Apps`): `ToolboxPackage.Write` writes the `.mltbx` as R2025b's `packageFromOptions` does, part for part - `[Content_Types].xml` with a default per extension present, the relationships, `fsroot/` with the files sorted and `DesktopToolset.xml` for the gallery files, `addonProperties`, `configuration` when there are path folders, `coreProperties`, `filesystemManifest`, `mwcoreProperties`, `mwcorePropertiesExtension`, `mwcorePropertiesReleaseInfo`, the screenshot and `systemRequirements` - and text for text where R2025b's text could be compared, but unsigned: JGraph cannot sign as MathWorks does, and R2025b reads and installs an unsigned package (`w13_variants`, `w13_readback`). The release-information part carries R2025b's own build stamp verbatim, because R2025b's reader validates it and refuses any other ("ReleaseInfo is invalid"). `ToolboxPackage.Read` reads R2025b's packages and JGraph's; `MlappInstallPackage.Read` reads the legacy `.mlappinstall` (JGraph writes none: R2025b's App Designer writes a toolbox, WO4). `AppPackageDetails` reads an app's name, version, author, summary, description and uuid from an `.mlapp` or a plain-text app for the gallery entry and the app card.
- **The add-ons folder** (`InstalledAddOns`): `%APPDATA%\JGraph\Add-Ons`, or what `JGRAPH_ADDONS` names, laid out as R2025b lays out `MATLAB Add-Ons`: a toolbox under `Toolboxes\<Name>` with its files and R2025b's resources files (the core, the path entries, the gallery registration, the screenshot), an app under `Apps\<dir>` - the folder named by R2025b's `convertNameToDir` - with its files, the core (plus JGraph's own `entryPoint` element, since no wrapper class is written) and the gallery registration. The gallery is every installed app and every toolbox's registered tools, each with the folders its run puts on the path (`AppUtil.genpath`'s rule for an app).
- **The builtins** (`JgsBuiltins.AddOns`, sixteen names): `matlab.addons.toolbox.ToolboxOptions` as a built-in class whose constructor takes `(folder, identifier, Name, Value, ...)`, its properties in R2025b's order and defaults (the name the folder's, the output file beside the folder, the folder's own files when none are named and the path derived from them only then), each set checked in R2025b's words (the identifier, the version's two to four numbers, the releases' spelling and range, a gallery file's kind and presence among the files, a path folder's files, an image's format, the read-only two); `packageToolbox` (an options object; a project file refused, JGraph having no toolbox projects), `toolboxVersion`, `installToolbox` (an earlier install with the same identifier replaced, the folders put on the path as R2025b puts them), `installedToolboxes`, `uninstallToolbox` (the struct's `Guid`, R2025b's odd refusal text for anything else, a warning for one not installed); `matlab.apputil.install` (the extension added when left off, the folder named as R2025b names it, 'installed' or 'updated'), `uninstall`, `run` (the id's start is enough when it names one app; the app's folders on the path, the entry point called), `getInstalledAppInfo` (the struct array, or with no output R2025b's two columns or the note that none are installed), `create` (R2025b's removal warning, then a refusal: JGraph has no packaging dialog) and `package` (no apps projects: not found, or not a valid project); `matlab.addons.installedAddons` (a table of JGraph's add-ons), `install`, `uninstall` and `isAddonEnabled`.
- **The share window** (`AppShareWindow`, kind MatlabApp, "Configure MATLAB App for Sharing", 675 by 990): App Appearance says the app will be packaged as a MATLAB toolbox and installed in the Apps tab and shows the app card - the thumbnail or the default app icon, the name, "by" the author, the summary, "version" the version, each line only with words - then the files required and Package; Show Code as on the standalone page, no package type. Package runs `AppShareScript.MatlabApp` - R2025b's script with a fresh identifier, the app first among the toolbox files, the files' folders as the path, `release\<app>.mltbx` as the output, the two printed lines in words rather than through R2025b's message catalog - under the packaging dialog's one step.
- **The Apps menu** (`ScriptWorkspaceWindow.Apps`): the gallery's entries, each with its icon when one is kept and its summary as a tip, run in the MATLAB session as the gallery's buttons run them (an app through `matlab.apputil.run`, a toolbox's tool with `addpath` of its folders first); Install App… over an `.mlappinstall` or `.mltbx` through the matching builtin; Uninstall listing what is installed; Open Add-Ons Folder. The menu reads the folder again each time it opens.
- **The designer**: `AD_SHARE_MATLAB` is live and shares as Standalone Desktop App does (the app saved first, one window per app).

## Consequences

- `JGraph.Deploy/Apps/ToolboxPackage.cs` (with `ToolboxPackageOptions`, `ToolboxPackageInfo`, `ToolboxGalleryEntry`), `MlappInstallPackage.cs`, `InstalledAddOns.cs` (with `InstalledToolbox`, `InstalledApp`, `GalleryEntry`), `AppPackageDetails.cs`; `AppShareScript.MatlabApp`; `JgsBuiltins.AddOns.cs` and `JgsBuiltinClasses.AddOns.cs`, registered beside the compiler builtins and listed in the catalog, the dispatch table (sweep 34) and the nargout table; `AppShareWindow`'s second kind, `AppDesignerWindow.Share`'s second command, the toolstrip's row, `DesignActions`' live set; the shell's `AppsMenu` and `ScriptWorkspaceWindow.Apps.cs`; the coverage doc's row.
- A built-in class whose name is also a builtin function needs a native constructor method of its own name: once `interpreter.BuiltinClass` has declared it, the dotted name resolves to the class, whose default constructor refuses arguments ("Too many input arguments", found with a first-chance stack).
- The three packages R2025b wrote are fixtures (`tests/JGraph.Tests/Deploy/fixtures`).

## Measured

- **R2025b headless** (`ui-probes/w13`): `w13_apps` (the scripts, the parts, the install layouts, forty-odd refusals), `w13_installed` (the resources R2025b writes beside an installed toolbox and app), `w13_variants` (R2025b reads its own package with the signature stripped; JGraph's failed on the release-information part alone, and read once that part is R2025b's), `w13_warn` (R2025b warned "not supported for this MATLAB release or for this platform" on JGraph's package while the platform flags were written false - a logical read wrongly, fixed - and not on R2025b's own unsigned package), and `w13_readback`: **R2025b reads, installs, lists, puts on the path and uninstalls the toolbox JGraph's Share > MATLAB App wrote**, its gallery registration in place. Everything the probes installed into R2025b was uninstalled by them.
- **Tests**: `AddOnsTests` (11): R2025b's packages read back; JGraph's package has R2025b's parts in R2025b's order but the signature, with `[Content_Types].xml`, `DesktopToolset.xml`, `addonProperties`, `configuration`, `systemRequirements`, `mwcoreProperties` and the relationships equal to R2025b's text for the same files; the screenshot part; R2025b's toolbox and app installed into a folder of the test's own with R2025b's layout, listed, replaced, uninstalled; the folder name's rule; the details of an `.mlapp` and a plain-text app; the MATLAB App script against the probe's recording. `AddOnBuiltinsTests` (5): twenty-eight refusals in R2025b's words, `packageToolbox` writing and `toolboxVersion` reading, a toolbox's install putting its `helper.m` on the path and its uninstall taking it off, an app's install, listing, update and uninstall through `matlab.apputil`, `installedAddons`' table. With the share script, toolstrip, designer, compiler apps and installer suites, 125 pass.
- **The window check** (`run-w13designer.ps1`, 37 checks pass): Share > MATLAB App over `w4/W4App.m` - the SHARE drop-down, the window with the app card's title and version, the analysis, no package type, Show Code's lines, Package with the dialog's step and result, the toolbox at `release\W4App.mltbx`; then a second launch whose `-r` file installs that toolbox through `installToolbox` into an add-ons folder of the check's own (`JGRAPH_ADDONS`), the layout with R2025b's resources files, the shell's Apps menu listing W4App, its entry run (the app's window up, pictured, closed through `WindowPattern`) and Uninstall > W4App emptying the folder. I looked at the pictures of the share window and the running app.
- **Older checks on this source**: `run-w12designer.ps1` passes (the share window's two kinds share one class).

## Not measured

- **R2025b's own share window and Apps gallery** were not seen on screen; the page was read from its bundle.
- **The Apps menu's Install App…** is a file dialog, not driven; the install runs through the `-r` file instead.
- **An app with required files** was not shared in a window; the script's `ToolboxFiles` and `ToolboxMatlabPath` for several folders are covered by the script test.
- **A toolbox with a getting started guide or an `info.xml`**: the configuration's documentation paths are not written.
- **`matlab.apputil.run` of an installed app** runs only in the window check (the gallery's W4App), not in a test.

## Divergences

- **The package is unsigned**: R2025b signs with MathWorks' key; JGraph cannot, and R2025b accepts an unsigned package.
- **The release-information part is R2025b's build stamp verbatim**, since R2025b's reader validates it; JGraph's version is not in the package.
- **No "Manage App Sharing with a MATLAB Project" pane** and no `RequiredAddons` in the script (JGraph has no add-on repository).
- **The two printed lines are words**, not R2025b's `message` catalog ids.
- **`installedAddons` lists JGraph's add-ons alone** (R2025b lists its products too), with a numeric Enabled column, and every add-on is enabled; no `enableAddon`/`disableAddon`.
- **`matlab.apputil.run` calls the entry point directly**: no wrapper class, reference count, `mlock` or shadow check, and the app's folders stay on the session's path afterwards; `getInstalledAppInfo` lists the apps alone, as R2025b's does.
- **A toolbox's path folders are on the session's path only until the session ends**; R2025b's are permanent. The Apps menu adds them again before a run.
- **`matlab.apputil.create` and `package` refuse**: JGraph has no apps projects and no packaging dialog.
- **A second `installToolbox` of the same identifier replaces the install**; R2025b's `install` does so by its default option, its `installToolbox` was not measured with a second install.
- **A bare dotted mention of `matlab.apputil.getInstalledAppInfo` answers its value as `ans`** where R2025b prints the table; the parenthesised call prints as R2025b's does.
- **The look is JGraph's**: WPF expanders and a bordered card, not the web page's title panes and app card.
