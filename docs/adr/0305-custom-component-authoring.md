# ADR 0305 — Custom UI component authoring: the component's class, its dialogs and tabs, Configure for Apps and the registry

## Status

Accepted, 2026-11-04. Stage W15 of the App Designer window plan (chip 162): a custom UI component authored in App Designer as R2025b's code engine writes one - the Start Page's component tiles, the class text with its events, managed properties, `update` and `setup`, the `.mlapp` with its `AppTypeData`, the Add Property and Add Event–Public Callback Pair dialogs, the Event–Callback Pairs tab, the toolstrip swapped for a component, Run as a component, Configure for Apps with the "App Designer Custom UI Component Metadata" dialog, and `appdesigner.customcomponent.configureMetadata` and `removeMetadata` writing `resources/appDesigner.json`.

## Context

Since DS7b (ADR 0252) the designer puts a registered custom component in its library and on its canvas, but could not author one: the Start Page's Blank Component tiles were disabled (W3), `DesignStartPage.NewText` refused them, and the registry was read, never written. R2025b's App Designer writes a component's class through a code engine configured for the `CustomUIComponent` app type (`ComponentAppCodeEngineConfig` and its behaviors in the client: the object is `comp`, the lifecycle methods are `setup`, `update` and `postSetup`, the startup function is `postSetupFcn` under `PostSetupFcn`, the root's code name is `CustomUIComponent`, the managed properties are grouped by their sorted attributes into `properties (...)` blocks each followed by an indented blank line, the events stand in `events (HasCallbackProperty, NotifyAccess = private)` sorted by name, the underlying components in `properties (Access = private, Transient, NonCopyable)` or, with Give Test Cases Access, `properties (GetAccess = ?matlab.unittest.TestCase, SetAccess = private, Transient, NonCopyable)`); its `.mlapp` carries the events, the managed properties and the `update` method in `CodeData.AppTypeData`. The engine's output was derived from those behaviors and measured headless (probe `w15_component`, templates comp1..comp4): each text compiles and runs in R2025b - construction with and without a parent, the managed properties' class, size and validation, the events and their callback properties, the button's push through `matlab.apps.createCallbackFcn`, `update`'s write, `postSetupFcn`; a control `.mlapp` written through `MLAPPSerializer` with the client's `AppTypeData` was read back through `loadApp` for the shapes (`HasCallbackEvents` as an N-by-1 struct with `Name` and `Description`, `Methods.update` with `Name` and a `Code` cell, `ManagedUserProperties` as an N-by-1 struct with `Name`, `Description`, `DataType`, `DefaultValue`, `Size`, `Attributes` without `Access = public` and `ValidationFunctions` with `InputArguments` only when any has them; the loader adding `CallbackPropertyEvents`, `AllowTestCaseAccess`, `Methods.postSetup` and the `Inferred*` fields); App Designer's Run of a component (`UserComponentRunner`: the class called in the base workspace, the figure it makes marked `IsRunningInAppDesigner` and `RunningInstanceFullFileName` and sized to the component's far corner, the earlier instance closed by deleting its parent); the metadata functions (`getValidatedCustomComponentFile`'s refusals in their identifiers and words, the headless call drawing the "App Designer Custom UI Component Metadata" uifigure, `MetadataUIViewModel`'s defaults - the description from `help`'s first line, the category "My Components", version 1.0 - and its checks, the `Model`'s `registerComponent`, `updateComponent` and `deRegisterComponent` and the file they write: `jsonencode` with PrettyPrint, two-space indents, the component's keys in merge order, `schema` 3 and `MATLABRelease` last, no trailing line break, `components: []` after the last removal); and the Add Property dialog's validation (`validateAndInferPropertyDetails`: a char default under `double` becomes its codes, a number under `logical` a logical, the size messages, the validators' texts, the inferred editors). Two R2025b faults were measured: the wrong-extension refusal names the extension it was given ("must have a .txt extension"), and `removeMetadata` without a registry file fails on its own `isKey` (`MATLAB:UndefinedFunction`).

## Decision

- **The code model** (`Designer/DesignComponentCode`, `DesignCode`, `DesignCodeWriter`, `DesignClassWriter`, `DesignCodeReader`, `Jgs/JgsMlappLayout`): a component's text is the engine's, line for line - `DesignCodeEvent` (name, description, `NameFcn`, `notify(comp, 'Name');`), `DesignManagedProperty` (name, description, data type, default, size, validation functions with their arguments, the attributes sorted with the access among them, `AbortSet` bringing `GetObservable` and `SetObservable`), the blocks they make, the editable section, the callbacks, the lifecycle block with `update`'s body and `setup`'s root lines (Position and the inherited properties that differ from their defaults), the children under `comp` with `matlab.apps.createCallbackFcn(comp, @X, true)`, the postSetup call. The text is the truth: the `.mlapp`'s `AppTypeData` is written from it (`DesignComponentModel`) and never read. The layout tells a managed block from a user's `properties` block by a rule: the block's attributes are the dialog's, every declaration parses as a managed one, and its attribute key is not below the previous managed block's (the engine writes them ascending).
- **The document** (`DesignDocument.Component`, `DesignRuntime.Component`): events added, changed (the user's `notify` calls renamed with them), removed; managed properties added, modified (the user's `comp.Name` renamed, the update body among the user's lines) and removed, each default checked as `validatePropertyValue` checks it and the inspector's edit of a default put into R2025b's canonical text; the update body edited in the Code View; Give Test Cases Access; every edit one undoable step.
- **The window** (`AppDesignerWindow.Component`, `AppDesignerDialogs.Component`, `DesignCodeBrowserView`, `DesignEventPairsView`, `DesignInspectorView.Component`, `DesignCallbacksView`): the toolstrip as `updateForDocumentType` shows it for a component (the Callback split button, Event and Configure for Apps shown; App Details, SHARE, App Input Arguments and Convert gone); the Property buttons and the Code Browser's Properties add opening the Add Property dialog (name, access, data type, size, default, the validation functions by category with their arguments, description, attributes; a refusal shown in the dialog); Event from the toolstrip, the Callbacks tab's split, the Events tab and the Event–Callback Pairs tab (the properties panel's third tab, shown while the component's root is selected) opening the Add Event dialog, which previews the callback property and the trigger line with a Copy button; the inspector showing the root's public managed properties under the class's name and Testing's "Give Test Cases Access"; the Callbacks tab's PRIVATE CALLBACKS and PUBLIC CALLBACKS; Save As and Save Copy As as `.mlapp` only; Run through `DesignRun.Run`, which runs a component file as `RunComponent`; Configure for Apps saving the component and asking the MATLAB session for `appdesigner.customcomponent.configureMetadata`, whose dialog comes back through the session's `IScriptAppDesigner.ConfigureMetadata` door.
- **The metadata** (`Designer/DesignComponentMetadata`, `Jgs/JgsBuiltins.ComponentMetadata`, `DesignRun.CheckComponent`): the registry read, checked and written as R2025b's `Model` and `SchemaUtils` do - the root folder above the `+package` and `@class` folders, a record missing a required key filled in with the schema's defaults, an unreadable file invalid (the dialog warns and overwrites), a fresh record in the dialog's key order, an update merged key by key, `schema` and `MATLABRelease` set on every write, the file in `jsonencode`'s PrettyPrint form through `JgsJson`'s own quoting; the dialog's checks (a blank name or category, a version not `Major.Minor`, an email not an address) and words; the component made once in the session in an invisible figure for its `defaultPosition`, with R2025b's three checks (`Units` pixels, no other child added to the parent, no public callback assigned) and the abstract class's message; the two builtins with `getValidatedCustomComponentFile`'s refusals, a `.m` or `.mlapp` class found as given, in the current folder or on the path, and the class checked for the container among its superclasses through the files' headers; JGraph's own 24-by-24 default icon. The names are in the catalog, the nargout table and the dispatch table (sweep 38).
- **The interpreter**, where the engine's own texts found it short: a property validator written with the property's name among its arguments (`Limits {mustBeNumeric(Limits)}`, `Value {mustBeInRange(Value, 0, 100)}`) reads the value under validation by that name; `GetObservable` is accepted; `matlab.apps.createCallbackFcn` is the package function R2025b ships, for any object; a dotted built-in whose head is itself a built-in function (`appdesigner.customcomponent.configureMetadata`) is the name meant while no variable holds the head.

## Measured

## Not measured

- **R2025b's own window** over a component: the inspector's look for the root, the Event–Callback Pairs tab's columns, the Add Property dialog's validation-function picker (a grouped list with placeholders; JGraph's is a checked list with argument boxes).
- **The avatars**: R2025b photographs the component in a light and a dark figure (`getframe`) for the library's drag preview; JGraph writes both empty.
- **A component in a class folder** (`@Gauge`) and a component whose superclass is another component of the user's on the path (the check reads the files' headers rather than loading the classes).
- **The registry held by App Designer's cache** (`matlab.internal.regfwk`): JGraph's open apps read their libraries again when the dialog writes.

## Divergences

- **The avatars** are written empty; the library's drag preview of a JGraph-registered component is blank.
- **The wrong-extension refusal** names the two extensions taken ("must have a .m or .mlapp extension") where R2025b names the one it was given; `removeMetadata` with no registry file does nothing where R2025b fails on its own `isKey`; an unreadable registry is refused under R2025b's identifier with the warning's first sentence, R2025b's catalog having no text for it.
- **The metadata dialog** is the app's window and modeless, refused in a session with no window, where R2025b draws a uifigure even headless; its Help is a message rather than the documentation page.
- **A managed block** is told from a user's by the text rule above, so a user's own block that fits it after a managed block is read as managed and written back in the engine's form.
- **The inspector** shows the root's public managed properties and Testing, not its inherited BackgroundColor, Visible, Interruptible, BusyAction and HandleVisibility (written in `setup`).
- **The toolstrip's `${0}` texts** (Help Text, the private property's tip) still say App for a component.
- **A packaged component** (`+pkg/comp.mlapp`) is run by its bare name from its own folder, as apps are (ADR 0253).
- **`+` and `@` folders** are read as whole path segments; R2025b takes any such character in the path as one.
