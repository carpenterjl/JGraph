# ADR 0304 — The Code Analyzer: `checkcode`, `codeIssues`, the editor's marks and App Designer's coding alerts

## Status

Accepted, 2026-11-04. Stage W10 of the App Designer window plan (decisions WD4 and WO5): JGraph's Code Analyzer over the MATLAB parse tree with R2025b's first set of checks, the builtins `checkcode`, `mlint` and `codeIssues`, the marks, message bar, hover text and Fix in the shell's editors and App Designer's Code View, and App Designer's own coding alerts.

## Context

JGraph had no Code Analyzer: no `checkcode`, no `mlint`, no `codeIssues`, and its editors underlined nothing. R2025b's analyzer is closed (`mlintmex`), so its checks were measured rather than read: W0 ran `codeIssues` over 576 files (the 44 shipped apps, JGraph's parity fixtures, the examples) and ranked 106 check ids by the files they appear in (`w0_analyzer`); decision WO5 took the first set as the top of that ranking, each with R2025b's id, text and severity, the rest refused silently. Two probes then wrote small files to raise each check and recorded what `checkcode -id -struct` says about them (`w10_analyzer`, `w10_rules`: 213 messages over 19 files): the span each message marks (a name, a whole call, a statement to its semicolon, the operator alone), which forms raise a check and which do not (`strcmp(upper(a), 'abc')` is STCUL where `'ABC'` is STCI; `[f(x)]` keeps its brackets where `[x]` loses them; a `clear` or a `load` is noted in a function and not in a script; `eval` quiets DEFNU for the whole file; a function's object argument unused is MANU, any other INUSD; `x = 1; x = 2;` marks the first; an output set in one branch is set), the display forms (`L 14 (C 10-15): message`, `C 1` for one column, the `==========` file headers, the `-text`, `-fullpath`, `-cyc`, `-modcyc`, `-notok` and `-severity` switches, an unknown option noted on line 0), the struct's fields and their order (which differs when it is empty), the two outputs over a cell or a string array of names, the refusals in R2025b's identifiers and words, `codeIssues`' object display with its "Issues table preview", its `Issues` and `SuppressedIssues` tables, the `Files` order (case set aside) against the issues' order (ordinal), `fix` by check id and the status table it answers, and the `%#ok` comments: `%#ok` alone, `%#ok<A,B>`, `%#ok<*A>` for the file, the file-wide form winning, a comment that suppressed nothing marked MSNU on the comment or on the idle id, an id no check has marked MSNE, a second `%#ok` on a line unread. The McCabe counts were measured too (a `switch` counts its cases, once in the modified count). App Designer's coding alerts were read from its client (`ProgrammingAlertPlugin`, `SupportedGraphicsFunctionTip`, `GraphicsFunctionList.json`, the `ProgrammingTip` strings): a graphics function called in the user's code without an axes - no `app.UIAxes` first and no `'Parent', app.UIAxes` - is marked "Specify an Axes handle as first argument." (or "Specify an Axes as the value for 'Parent'." for one that takes only a parent), line by line over the editable lines with comments stripped and continuations joined, one alert per line, none where the name is in a string, in a command, in a `function` line, after a dot or called with `app` itself; the alerts rest while `ShowProgrammingTips` is off.

## Decision

- **The analyzer** (`Scripting/Analysis/JgsCodeAnalyzer`, `ScopeAnalysis`, `PatternChecks`, `CodeChecks`, `SourceSpans`): static, over the MATLAB parse tree and the token stream the parser read. One scope per script, function, local, nested and method, with what it assigns (what makes a name a variable), its parameters and outputs, its globals and persistents, and every read and assignment in order; from those the unused family (INUSD, MANU, NASGU, ASGLU, STRNU, STOUT, NUSED, PUSE, PSET, NODEF, DEFNU, REDEFGG, LTARG), what cannot run or does nothing (UNRCH, VUNUS, NOEFF, EQEFF, NOPTS, NOPRT, NOCOMMA, NOSEMI), the loop checks (AGROW, LAXES), the calls (CHARTEN, FVAL, EXIST, EVLCS, EVLEQ, EVLDUAL, EV2IN, CLEAR0ARGS, CLALL, CLFUNC, LOAD, SUBSASGN, DSPSP, STRQUOT, LOGL, RPMT1, RPMT0, RPMTT, RPMTF, STCI, STNCI, STCUL, STLOW, GFLD, SFLD, ELARLOG, ISCL, ISMT, ISMAT, NBRAK2, NO4LP, GVMIS, NOANS) and the functions not recommended (DATST, DATNM, DATE, TNOW1, HIST, DQUAD, DQUADL, DQUADV, DDBLQD, DTRIQD, COMPASS, DINLN, ST2NM): 73 checks, each with R2025b's id, severity, text and span, a fix where R2025b offers one (an argument to `~`, `char(10)` to `newline`, `repmat(1, ...)` to `ones(...)`, `strcmp(upper(a), b)` to `strcmpi(a, b)`, the idle `%#ok` taken out, the unused `global` line deleted, a semicolon added), and the McCabe counts. A file the parser refuses is one SYNER message. The analyzer is R2025b's as measured: where a rule could not be told from the probes (NODEF across a loop, DEFNU beside `eval`, FVAL over a variable that holds a name throughout, `strcmp(lower(s), 'abc')` with `s` a constant) the measured answer is reproduced, not a guess; a check the measurement did not settle (DFCNCHK) is left out, since no message is better than a wrong one.
- **The comments** (`%#ok`): `%#ok` alone suppresses every message on its line, `%#ok<A,B>` those ids, `%#ok<*A>` an id in the whole file, the file-wide form first; a comment that suppressed nothing is MSNU on the comment or on the idle id, an id in neither JGraph's checks nor R2025b's list is MSNE, and an id R2025b has that JGraph does not is left alone. Suppressed messages are kept with how they were suppressed, for `codeIssues` and `-notok`.
- **The builtins** (`Jgs/JgsBuiltins.CodeAnalyzer`, `JgsBuiltinClasses.CodeAnalyzer`): `checkcode` and `mlint` in R2025b's forms - the display (no `opentoline` links, as a session with no hot links prints none), `-id`, `-string`, `-struct`, `-fullpath`, `-text`, `-cyc`, `-modcyc`, `-notok`, `-severity`, a cell or string array of names with the file headers, two outputs, the struct's fields in R2025b's two orders, and the refusals; `codeIssues` as a value class with `Date`, `Release` (JGraph's version), `Files`, `CodeAnalyzerConfiguration`, `Issues` and `SuppressedIssues` as R2025b's tables, over files, folders (with `IncludeSubfolders`) and the current folder, its display with the "Issues table preview", `fix` by check ids rewriting the files and answering the status table, `export` refused. The names are in the catalog, the eval list, the nargout table and the dispatch table (sweep 37).
- **The editor** (`Controls/Scripting/ScriptEditorControl.Analysis`, `CodeMessageRenderer`, `MessageIndicatorStrip`): a host hands the messages over; the editor underlines their spans (red, orange, a dotted line for a suggestion), lists them on a message bar right of the scroll bar - a square green, orange or red at the top that takes the caret to the next message, a Fix button under it for the message at the caret, a mark per line that a click goes to - shows a message's text when the pointer rests on it, and applies a fix by its edits to the document (the button, Alt+Enter, the context menu's Fix item). The automation status gains `; Messages N`, and the square's `ItemStatus` lists each message's id and span, so a window check reads the bar without a picture.
- **The shell** (`ScriptWorkspaceWindow.Analysis`): a MATLAB document is analyzed when it opens and half a second after its last keystroke, as R2025b's editor analyzes as you type; a JGS document is not, the checks being MATLAB's.
- **The designer** (`AppDesignerWindow.Analysis`, `Scripting/Analysis/DesignCodingAlerts`, the setting `matlab.appdesigner.codeview.ShowProgrammingTips`): the class text as the Code View shows it is analyzed when the app opens, after the designer writes the class again, and half a second after the last keystroke (R2025b's plugin waits 500 ms); App Designer's coding alerts join the messages on the editable lines, one per line and not on a line the analyzer already warns about, as R2025b's plugin adds them, while "Enable app coding alerts" is on; "Disable coding alerts" is an item of the code view's context menu.
- **The parser** takes two forms it refused and MATLAB takes: a trailing comma in a bracket or brace literal (`[1, 2,]`, `[1, 2,; 3, 4]`) and a parenthesized `for` header (`for (k = 1:n)`), which the analyzer's NBRAK2 and NO4LP need to see.

## Consequences

- `JGraph.Scripting/Analysis/` (`CodeMessage.cs`, `CodeChecks.cs`, `SourceSpans.cs`, `ScopeAnalysis.cs`, `PatternChecks.cs`, `JgsCodeAnalyzer.cs`, `CodeFixer.cs`, `DesignCodingAlerts.cs`); `Jgs/JgsBuiltins.CodeAnalyzer.cs`, `Jgs/JgsBuiltinClasses.CodeAnalyzer.cs` and the declaration door, the catalog, `EvalBuiltinNames`, the nargout table (sweep 37), the dispatch table (2,487 names), `JgsValue` (the `codeIssues` footer; a string array of several elements summed up as `[R×C string]` in an object's display); `Parser` (the trailing comma, the parenthesized `for`); `Designer/DesignSettings` (`ShowProgrammingTips`); `JGraph.Controls` (`ScriptEditorControl.Analysis.cs`, `CodeMessageRenderer.cs`, `MessageIndicatorStrip.cs`, the XAML's bar, the hover reading a message first, the status); `JGraph.Application` (`ScriptWorkspaceWindow.Analysis.cs`, `AppDesignerWindow.Analysis.cs`, the hooks in `AddDocument` and `AddApp`).
- `tools/matlab-checklist/ui-probes/w10/` (`w10_analyzer.m`, `w10_rules.m` and their outputs), `tools/matlab-checklist/dispatch/dispatch_probe37.m` and its outputs, `tools/runtime-checks/run-w10designer.ps1`, the parity fixture `w10_checkcode` over `helpers/w10_analyzed.m`.

## Measured

- **Tests**: `CodeAnalyzerOracleTests` (20 files from the two probes replayed: every message R2025b raised whose check JGraph has is raised with the same id, line, columns and fixability, and nothing R2025b did not raise is - 213 messages, 19 files, 73 checks; one more holds that every id R2025b raised is a check of JGraph's or on its list), `CodeAnalyzerTests` (the fixes rewriting the probe files as R2025b's fixes do, the suppressed list with its kinds, the MSNU fixes, the complexity counts, SYNER, the parser's two new forms, the coding alerts over a callback's lines), `CodeAnalyzerBuiltinTests` (`checkcode`'s displays, outputs and refusals, `codeIssues`' tables, folder walk, orders, display, refusals and `fix` writing the files): 21, 12 and 10; the parity fixture `w10_checkcode` over `helpers/w10_analyzed.m`, recorded from R2025b, agrees line for line (25 messages, the `-string` text with `-cyc`, the tables' columns and values); 1,613 pass with the designer, toolstrip, debugger, parser, lexer, command-syntax, editor, comparison, file-index and resolver suites.
- **The window check** (`run-w10designer.ps1`, JGraph.Application in Release): all 20 checks pass - a `-r` file opens a plain-text app whose startup function calls `plot(x)` without an axes, writes `y = char(10)` and leaves `z` unused; the Code View's status counts three messages; the bar's square says warning and lists `APPAXES 16:13-16; CHARTEN 17:17-24; NASGU 18:13-13`; the caret put on the `char(10)` line through Go To enables Fix, which rewrites the line and drops the message; Save writes `y = newline;` to the file; the square takes the caret to a message's line. I looked at both pictures: the orange waves under `plot` and `z`, the line under `char(10)`, the bar with its square, Fix button and marks; after the fix `newline` in the text and two marks left.
- **Sweep 37**: `checkcode` and `mlint` are m-files with a variable `nargout`, `codeIssues` a class file with one output.

## Not measured

- **R2025b's own window**: the look of its underlines, message bar and Fix; JGraph's bar is its own (a square, a Fix button, marks), and R2025b's Fix sits in the message's tooltip.
- **The checks past the first set** (the other 33 ids of W0's ranking, SEPEX, MDUPC, BDLGI, BDSCI and the device-class checks among them) and R2025b's full list of ids: a `%#ok` naming an id outside both lists is MSNE, which R2025b's fuller list might not say.
- **Constant tracking**: R2025b reads a variable's constant value in more places than the two measured (`feval(fn, 1)` with `fn = 'sin'`, `strcmp(lower(s), 'abc')` with `s = 'abc'`); JGraph reads it in those two.
- **`fix` by a table of issues**, `export` to SARIF or SonarQube, and `checkcode` over `.mlx` files.
- **The shell's editor** was not driven by a window check (the designer's Code View was, over the same control).

## Divergences

- **The first set** is 73 of R2025b's checks; the rest are not raised, and a `%#ok` naming one of them is left alone.
- **A parse error** stops the analysis at one SYNER message, where R2025b goes on past it; a file JGraph's parser refuses that MATLAB takes is marked SYNER.
- **`checkcode`'s display** prints no `opentoline` or `edit` links; the file headers and lines are R2025b's words.
- **`codeIssues.Release`** is JGraph's version, its `Severity`, `Fixability` and `Suppression` columns are categorical where R2025b's are enumeration classes, its `Date` is JGraph's clock; `export` is refused; `fix` takes check ids, not a table; a fix inside an `.mlapp` is not written by `fix`.
- **STCI's fix** unwraps both arguments (`strcmpi(s, 'ABC')`) where R2025b's left `upper('ABC')`; NBRAK2's fix takes a trailing comma with the brackets where R2025b's left it.
- **NOEFF** in a function (`x(1);` with `x` a variable) is not raised, as measured; in a script it is.
- **The coding alerts** carry the id `APPAXES` in JGraph's lists (R2025b's have none), and "Disable coding alerts" is a context-menu item rather than a check box under the tip.
- **The message bar** and the Fix button are JGraph's; R2025b's Fix is in the tooltip.
