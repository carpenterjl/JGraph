# ADR 0299 — The editor's code folding, display settings, zoom, split document and Print

## Status

Accepted, 2026-11-01. Stage W9c of the App Designer window plan, the last of W9: the VIEW tab and the FILE section's Print. W9a (ADR 0297) has Find and Replace, Go To's line and bookmarks; W9b (ADR 0298) the CODE section. With it W9 is finished.

## Context

The VIEW tab's controls were disabled, the Code View folded only App Designer's default blocks (W8d, ADR 0296), and the shell's editor had no folds, zoom or split. R2025b's rich text component holds the tools (`toolbox/matlab/rich_text_component/release/bundle.mwBundle.rtc_R2025b.js`): `rtc/plugins/folding/FoldingModel`, `FoldingController`, `FoldingActions` and `FoldCandidate`, with the MATLAB language's `MatlabMTreeFoldCandidateContributor`, `FoldableMTreeNodeTypes`, `FoldPreferences` and `FoldInitially`; `rtc/plugins/zoom/ZoomController`, `ZoomConfiguration`, `ZoomConstants` and `ZoomSettingsManager`; `rtc/plugins/splitscreen/SplitScreen`; `rtc/plugins/print/Print`; `rtc/plugins/currentlinehighlight/CurrentLineHighlight` and `CurrentLineHighlightPreference`; `rtc/plugins/linenumbers/LineNumberPreference`; and App Designer's `view/toolstrip/EditorTab` and `action/EditorAction` for what the VIEW tab binds. The folds have a MATLAB-side oracle: `mtree(text, '-comments')`, whose node kinds and line spans are what the contributor folds, run headless over the Smart Indent oracle's 360 programs (`ui-probes/w9/w9_folds.m`). The settings read headless: `codefolding.Fold*` on but `FoldIfElseBlocks`, `FoldSwitchCaseBlocks`, `FoldSections` and `FoldArgumentsBlocks`, `InitiallyFold*` all off; `displaysettings.ShowLineNumbers` true, `HighlightCurrentLine` false with `HighlightCurrentLineColor` [229 250 221], `DataTipsInEditMode` false, `EnableZoomOnScroll` true, `EnableSingleFileZoom` false, `CurrentZoomFactor` 1.

## Decision

- **Fold candidates** (`CodeFoldRules`): every block of the text that spans more than one line - `function`, `classdef`, `properties`, `methods`, `events`, `enumeration`, `for`, `parfor`, `while`, `try`, `spmd`, `if`, `switch`, each `case` and `otherwise`, `arguments`, a block comment, a run of two or more whole-line comments outside block comments and not a `%%` title, and a `%%` section to the line before the next - read from the Smart Indent lexer's block structure (`SmartIndent.Blocks`); a `case` and a function without `end` run to their last token, a comment's included, as `mtree`'s nodes do. The kinds folded are R2025b's settings: `if`, `switch` and its cases, `arguments` and sections stay unfolded. Folding hides the lines after a block's first; a fold the caret enters opens.
- **Collapse** (Ctrl+.) closes the innermost block holding the caret's line and puts the caret on its first line; **Expand** (Ctrl+Shift+.) opens it and every block around it (`getCandidateLineage`); **Collapse All** (Ctrl+,) and **Expand All** (Ctrl+Shift+,) every fold, the caret to the start of the innermost fold that took it. The Code View's candidates are every block of the class, with App Designer's default folds (W8d) and a plain-text app's appendix sections among them, the default folds closed when the text first shows; a MATLAB or JGS file in the shell reads its candidates again a moment after each edit, all open at first (`InitiallyFold*` off).
- **The display settings** (`EditorDisplay`, one set for every editor): line numbers, the current line shaded in R2025b's colour with no border, datatips while editing - the shell's datatips now come only with it on, or while paused in the debugger, as MATLAB's do. They are kept by R2025b's names (`matlab.editor.displaysettings.ShowLineNumbers`, `HighlightCurrentLine`, `DataTipsInEditMode`, `CurrentZoomFactor`) among App Designer's settings in the user's settings file, only where they differ from the factory values, and the Options dialog's save reaches them.
- **Zoom** (`ZoomRules`): R2025b's seventeen factors from 25% to 500%; Zoom In (Ctrl+Plus, Ctrl+=, the number pad's +) to the next, Zoom Out (Ctrl+Minus) to the one before, Reset Zoom (Ctrl+Alt+0) to 100% and disabled there; Ctrl+wheel steps once the wheel has turned past the threshold of 53, the accumulation starting again after each step. One factor for every editor (`EnableSingleFileZoom` off), scaling the code font.
- **Split Document**: Off, Left/Right or Top/Bottom; the second view is a second AvalonEdit editor over the same document with the same highlighting, read-only lines, shading and folds, mirroring the first's scroll and caret when opened (`_getDataToMirror`); a bar between them to drag; F6 switches the keyboard between the views (`_switchView`); Off gives the first view the second's place and caret when the second had the keyboard. Collapse, Expand and their All act in the view that has the keyboard.
- **Print** (Ctrl+P) and **Print Selection** (the selection's lines): the text in the editor's font and the highlighter's colours as a flow document through WPF's print dialog, the job named after the file.
- **Both windows**: the shell's View menu gains Highlight Current Line, Line Numbers and Datatips While Editing as check items, Zoom In, Zoom Out and Reset Zoom, Split Document (Off, Left/Right, Top/Bottom), Switch Screen Focus, Collapse, Expand, Collapse All and Expand All; its File menu Print and Print Selection. App Designer's VIEW tab is live - `AD_EDITOR_SPLIT_NONE`, `AD_EDITOR_SPLIT_LEFTRIGHT`, `AD_EDITOR_SPLIT_TOPBOTTOM`, `AD_EDITOR_HIGHLIGHT_CURRENT_LINE`, `AD_EDITOR_LINE_NUMBERS`, `AD_EDITOR_DATATIPS`, `AD_EDITOR_FOLD_CURRENT`, `AD_EDITOR_UNFOLD_CURRENT`, `AD_EDITOR_FOLD_ALL`, `AD_EDITOR_UNFOLD_ALL`, `AD_EDITOR_ZOOM_IN`, `AD_EDITOR_ZOOM_OUT`, `AD_EDITOR_RESET_ZOOM` - and so are `AD_EDITOR_PRINT` and `AD_EDITOR_PRINT_SELECTION` in the FILE section's Print drop-down; the buttons are forwarded to the Code View's editor, the toggles answer through the toolstrip's `Invoked` and follow the settings and the active app's split. Show Tips (`AD_EDITOR_CODE_VIEW_TIPS`) stays disabled: JGraph has no onboarding tips (stage X10).

## Consequences

- The rules stand free of a window in `JGraph.Scripting/Editing`: `CodeFoldRules` (with `FoldKind` and `FoldCandidate`) over `SmartIndent.Blocks`, and `ZoomRules`. `ScriptEditorControl.View` binds them with their keys, holds the split's second view and Print; `EditorDisplay` is the shared state every editor follows; `DesignSettings` knows the four display settings' names and defaults.
- The editor's `ItemStatus` says the folds closed of those there are, the zoom when not 100%, the split, and a display setting off its default - what the window check reads.
- `ScriptEditorControl.SetFolds` (W8d) now goes through `SetFoldCandidates`.

## Measured

- **R2025b's `mtree` headless** (`ui-probes/w9/w9_folds.m`, `FoldOracle.json`): the node kinds and spans of the 360 Smart Indent programs. `FoldOracleTests` (2) compares every block `CodeFoldRules` finds, sections apart, with `mtree`'s foldable nodes and the comment runs derived from its comment nodes - 358 programs, every one equal. Two mismatches were found and fixed on the way: a `case`'s and an `end`-less function's last line is that of their last token, a comment's too, not of their last statement.
- **Tests**: `EditorViewTests` (5: the default kinds, the candidate at a line and its lineage, comment runs, the zoom's steps, the wheel's threshold); `AppDesignerToolstripTests` gains rows for the live ids and Show Tips' stage. With the designer, App Designer, toolstrip, settings and editing suites, 205 pass in those suites.
- **The window check** (`run-w9cdesigner.ps1`, JGraph.Application in Release over an `.mlapp` in its Code View): all 58 checks pass - the default folds closed and not all, Collapse All and Expand All, Collapse at the caret moving it to the block's keyword past the indent and a second Collapse there folding nothing more (R2025b folds nothing already folded), Expand opening the lineage, Zoom In to 110% and 125% with the factor read from the settings file, Zoom Out, Reset Zoom disabled at 100% and the factory factor not written, the split Left/Right and Top/Bottom with the other toggle released and Off again, Line Numbers off, Highlight Current Line on, Datatips on and the defaults back, each read from the editor's status. I looked at pictures of the folds, the zoom, the split and the display.
- Every older designer window check passes on the final source (see the commit).

## Not measured

- **R2025b's own windows**: nothing was compared on screen.
- **Print**: a system dialog, not driven; the flow document's making is not under test.
- **In a window**: the keys, Ctrl+wheel, F6, the shell's menus, a dragged split bar, the Options dialog's save reaching the editors - the tests and the forwarding cover their rules.
- **`mtree` on a class's or a section's extent** beyond the oracle's programs; sections are not compared (`mtree` has no section node without `-cell`).

## Divergences

- **The split's second view opens with the default folds closed**, whatever the first view has open; each view folds on its own after that, as R2025b's do.
- **The current line's colour is the factory one**: a user's own `HighlightCurrentLineColor` is not read.
- **Print prints the text in the editor's colours through WPF's dialog**: R2025b prints through the browser with its own page layout, headers and the line numbers option.
- **No Show Tips**: the Code View's onboarding tips are not built (stage X10).
- **The display settings live among App Designer's settings** in JGraph's settings file, not in a MATLAB `settings()` tree, and the Options dialog has no page for them yet.
- **`InitiallyFold*` and the codefolding `Fold*` settings are R2025b's defaults**, with no setting of JGraph's own.
- **Sections fold only in the Code View's appendix**: a `%%` section is a candidate the setting leaves off, as R2025b's `FoldSections` does, and `mtree` was not asked for sections.
