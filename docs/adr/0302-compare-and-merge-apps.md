# ADR 0302 — Compare and merge apps: the Comparison Tool, `visdiff` and Compare To

## Status

Accepted, 2026-11-03. Stage W14 of the App Designer window plan (decision WD4): the line comparison R2025b's Comparison Tool draws, measured; `visdiff` with and without an output; the Comparison Tool window with Replace Content, Save Result and Publish; the DESIGNER and EDITOR tabs' Compare To and the tab menu's item; File > Compare To… in the shell.

## Context

App Designer's Compare To (`OPEN_FILE_COMPARISON_DIALOG`) was the one DESIGNER-tab button JGraph did not run. R2025b's road, read in place: `OpenFileComparisonDialogAction` saves a dirty or unnamed app (`SaveAppModelCommand`), then `comparisons_view_actions/gui/compareTo` opens a file chooser titled "Compare To" and calls `comparisons.internal.gui.compareInDesktop`; the `.mlapp` providers (`MlappDiffGUIProvider`, `MlappDiffNoGUIProvider`, type `OpcPackageMlapp`, priority 15) compare the generated class text (`getAppFileCode`) through `comparisons.internal.mlapp.mcosDiff`, and `comparisons.MlappComparison` holds `Left`, `Right` and `publish` (`createReport`); the merge side (`getAppCode`, `saveAppCode`) hands the client the code data's `EditableSectionCode`, `StartupCallback` and `Callbacks`, from which `isLinesMergeable` tells the user's lines from the generated ones ("Merging generated code is not supported."), and refuses apps saved in another release or with licensed components (`comparison.xml`). The text comparison itself is a closed engine (`mfzero SequenceDiffResult`, the `mw-diff` bundle), so it was measured: `w14_compare` ran `visdiff` with an output over 28 hand-made pairs, a seeded corpus of 30 edited programs and the W0 app pairs and parsed each report's rows (the glyph and the line of each side), and `w14_ties` over 48 small cases where two matchings are equally long. The measurements: the lines are matched by an exact longest common subsequence (white space, case and a trailing line break all count: a file ending in a line break has an empty last line); inside a run of unmatched lines a left and a right line pair up as one changed line only where they share a word (an identifier or a number), the pairs never crossing, the rest being the run's deleted lines, then its inserted lines; a text that occurs whole in the other is matched where it first occurs; and otherwise the choice among equally long matchings flips with the parity of the difference in line counts - the fingerprint of a search from both ends meeting in the middle. R2025b's own `visdiff` refuses an `.mlapp` against a `.m` and a folder pair without a window, 'binary' and other types with an output, and a comparison with neither an output nor a display, in the words `mldesktop.xml` holds.

## Decision

- **The engine** (`JGraph.Scripting/Editing/TextDiff`): `SplitLines` as the tool counts lines; `Compare` with the matching rule above - the shorter text contained in the longer first, then the table read from the end preferring the later left lines when the line counts differ by an even number and from the start preferring the earlier right lines when by an odd one, large texts anchored by their unique lines - and the word-sharing pairing of changed lines; `Hunks`; `Inline` boxing the characters a changed line alone has. It reproduces 102 of the 108 measured pairs; the six it does not are deeper ties, each differing only in which of equal lines is marked (open item 239).
- **The comparison** (`JGraph.Scripting/Designer/DesignCompare`): `FileComparison.Compare` of two files - two apps of either format as an app code comparison over their class text (a plain-text app's without its appendix, which the design covers), anything else as a text comparison; the designs' differences by code name (added, removed, moved, class changed, property changed with both values as the code writes them), which R2025b does not show; the right side's mergeable lines (the user's regions, `EditableLinesOf`, which the Code View uses too); the merge refusal for an app saved in another release read from `mwcoreProperties.xml` or the plain-text details; `Merge` of one difference left to right with a pure insertion placed after the right line before it; `SaveResult` writing the merged text as it is (an `.mlapp`'s class text with its model brought up to date, a plain-text app's class with its appendix kept); `HtmlReport` laid out as R2025b's "File Comparison Report" with the report's colours and glyphs, so that the W14 probe's parser reads it too.
- **`visdiff`** (`JgsBuiltins.Comparison`, `JgsBuiltinClasses.Comparison`): with an output a handle object of `comparisons.TextComparison` or `comparisons.MlappComparison` with `Left`, `Right`, `publish(c, Format=, OutputFolder=, Name=)` and `filter`'s refusal; without one the host's Comparison Tool through `IScriptComparisonTool` on the script context, refused without a window in R2025b's words; the type `'text'`; R2025b's refusals for a missing file, too few or too many arguments, a non-text argument, another type and folders.
- **The window** (`JGraph.Controls/Scripting/TextDiffView`, `JGraph.Application/Scripting/AppComparisonWindow`): "Comparison Tool - left vs. right" with the COMPARISON tab's words on a toolbar - Previous and Next (the Up and Down keys), Swap Sides, Refresh, Mergeable Only for two apps ("Navigate mergeable differences only"), Replace Content ("Replace content in right pane with content in the left pane"), Undo, Save Result and Publish to HTML - the summary line ("1 difference found. Use the toolstrip buttons to navigate to it.", "No changes detected", "The files are identical."), the two paths over the view, and for two apps a second tab with the designs' differences. The view shows the rows side by side in two read-only editors with the comparison's own line numbers, a filler row facing a line with nothing beside it, the report's colours, the characters that changed boxed, the glyphs in a gutter between, the two scrolled together and the current difference outlined. A merge marks the right pane "(Result)"; closing, Refresh and Swap Sides ask "Discard unsaved merge changes?".
- **Compare To**: the designer's command saves the app first as R2025b does, then JGraph's "Compare To" dialog (the other open apps offered, Browse), then the window, one per pair; the DESIGNER and EDITOR tabs' button and the tab menu's item run it; the shell's File > Compare To… does the same for its active file, saved first, and `visdiff` without an output opens the shell's window.

- `tools/matlab-checklist/ui-probes/w14/` (`w14_compare.m`, `w14_ties.m`, their outputs, `CompareOracle.json`, `CompareTiesOracle.json`), `tools/matlab-checklist/dispatch/dispatch_probe35.m` and its outputs, `tools/runtime-checks/run-w14designer.ps1`.

## Measured

- **The oracle**: `CompareOracleTests` replays the 108 measured pairs; 102 match row for row and the six known ties are held to the same number of matched lines; the W0 app pair with one edited callback line is the one changed row 37 it was.
- **Tests**: `DesignCompareTests` (7: two apps as an app code comparison with the designs' differences, Replace Content and Save Result writing the left line into the right app and reopening, an app saved in R2024b refusing merging, two text files merged and saved, the report's layout, the differences by code name, the editable lines), `VisdiffBuiltinTests` (3: the two comparison classes, `publish` with and without options, `filter`, and nine refusals in R2025b's words); 67 pass with the toolstrip suite.
- **The window check** (`run-w14designer.ps1`, JGraph.Application in Release): all 32 checks pass - `visdiff` from a `-r` file opens "Comparison Tool - W4App.m vs. W4App.m" over two plain-text apps that differ in a helper's line and a button's place, the summary for one difference, both titles, "Design comparison (1)", Mergeable Only shown, Next and Previous resting, Replace Content enabled and Save Result waiting; Replace Content marking the right pane "(Result)" with "No changes detected", Undo and Save Result enabled; Save Result writing the left's line into the right file and keeping its layout, the pane the file again; then App Designer's Compare To button, the "Compare To" dialog with its path set through ValuePattern, and the Comparison Tool opened from the designer with the same code and the design still differing. I looked at the pictures of both windows.
- **Sweep 35**: `visdiff` is a P-file with one output (`nargout` 1, `exist` 6), a `file` under every argument pattern.

## Not measured

- **R2025b's own window** was not seen; its words come from `toolstrip.xml`, `textdiff.xml`, `textmerge.xml`, `commonweb.xml` and `comparison.xml`; its merge mode was not driven, nor its three-way merge, filters, Find, Linked Scrolling or Save to Workspace.
- **The six ties**: a deeper rule of R2025b's search was not found (the bidirectional Myers search and diff-match-patch were tried and matched fewer pairs); the parity rule is the measured one.
- **Publish** and **Browse** are system dialogs, not driven; `publish` to Word and PDF is refused.
- **The shell's File > Compare To…** and the EDITOR tab's button were not driven (the same command as the DESIGNER tab's).

## Divergences

- **The tie rule** among equally long matchings is measured, not R2025b's: six of 108 pairs mark different equal lines.
- **An app against a plain file** is compared as text, where R2025b refuses it without a window; folders are refused in both forms, where R2025b's tool compares them.
- **`publish` writes HTML only**; 'docx' and 'pdf' are refused, and the report's Environment row names JGraph and its dialect.
- **The Comparison Tool's look** is JGraph's: a toolbar with the COMPARISON tab's words, no Merge Mode button (Replace Content is always offered), no Find, Linked Scrolling toggle, filters, Highlight, Save to Workspace or three-way merge, the right pane never typed into.
- **Compare To is JGraph's dialog** with the other open files offered, where R2025b opens a system file chooser.
- **A Design comparison tab** lists the designs' differences by code name, which R2025b does not show.
- **Save Result** writes the merged text as it is for both formats, a plain-text app's class compared without its appendix.
- **`visdiff` from a script** opens the shell's window, owned by the shell; the designer's windows are owned by the designer.
- **The summary line** uses the text comparison's words for an app comparison too, and "No changes detected" when it is the same.
